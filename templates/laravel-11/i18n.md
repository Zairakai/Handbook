# i18n

> **[Handbook][handbook]** › **[Templates][templates]** › **[Laravel 11][laravel-11]** › i18n

---

## Pattern overview

Translations are served **via API** from Laravel `lang/` files — no static JS translation files.

```text
lang/{locale}/*.php
      ↓
GET /api/v1/cache/trans/{lang}   (TransController)
      ↓
stores/i18n.ts (Pinia)           ← fetches, caches, exposes t()
      ↓
App.vue / components             ← t('common.hello')
```

---

## `lang/` files

Standard Laravel PHP translation files. Each file becomes a namespace in the JSON response:

```php
// lang/fr/common.php
return [
    'hello'  => 'Bonjour',
    'save'   => 'Enregistrer',
    'cancel' => 'Annuler',
];
```

```json
{ "common": { "hello": "Bonjour", "save": "Enregistrer", "cancel": "Annuler" } }
```

The `:app_name` placeholder is replaced server-side by `config('app.name')` before caching.

> `lang/` files must contain **UI strings only** — no role-specific or business-logic content. See [HTTP Layer — TransController][http] for the rationale.

---

## `config/i18n.ts` — single source of truth

The only file to modify when adding or removing a locale:

```typescript
export const defaultLocale   = 'fr'
export const fallbackLocale  = 'en'

export const availableLocales: Record<string, string> = {
  fr: 'fr',
  en: 'en',
}

export const transEndpoint = (lang: string) => `/api/v1/cache/trans/${lang}`
```

---

## `stores/i18n.ts` — Pinia store

Handles loading, caching, and applying locales:

```typescript
const store = useI18nStore()

// Load a locale (fetches once, then serves from in-memory cache)
await store.loadLocale('fr')

// Access the translator
store.t.value('common.hello')   // 'Bonjour'

// Current locale
store.locale   // 'fr'

// Whether any locale has been loaded
store.loaded   // true
```

### Behaviour details

| Scenario | Result |
| :--- | :--- |
| Known locale, not yet fetched | Fetches from API, caches, applies |
| Known locale, already cached | Applies from cache — no network call |
| Unknown locale | Falls back to `fallbackLocale`, fetches that instead |
| API returns non-2xx | Logs error, `loaded` stays `false` |

---

## `App.vue` — locale detection

Locale is detected automatically at `onMounted`:

1. `document.documentElement.lang` — the `lang` attribute on `<html>`, set by Laravel from `config('app.locale')`.
2. `navigator.language` — browser language, if no HTML attribute.
3. `defaultLocale` from `config/i18n.ts` — final fallback.

The detected value is passed to `store.loadLocale()`. If the value is not in `availableLocales`, it falls back to `fallbackLocale`.

---

## Adding a new locale

1. Create `lang/{locale}/*.php` files.
2. Add the locale to `config/i18n.ts` → `availableLocales`.
3. Set `APP_LOCALE` or `APP_FALLBACK_LOCALE` in `.env` if needed.

No frontend build changes required — the store fetches translations dynamically.

---

## Project-specific authenticated translations

If a project needs strings visible only to authenticated users (e.g. dashboard labels per role), create a dedicated endpoint in the project:

```php
// routes/api/v1.php — in the project, not the template
Route::middleware('auth:sanctum')->group(function (): void {
    Route::get('/user/context', UserContextController::class);
});
```

```typescript
// Fetch post-login in the auth store or a page component
await store.loadContext(token)
```

Do not modify `TransController` or `config/i18n.ts` for this use case.
